# web-kit

공용 키트를 사용할 때 혼동하기 쉬운 개념을 구별한다.

**결과 출처**: 표시 중인 조회 결과가 어떤 확정 검색 조건에서 나온 것인지의 관계다. 현재 조건의 결과가 아니면 선택·쓰기 대상으로 쓸 수 없는 이유가 된다.

**목록 복귀 문맥**: 상세·수정 등으로 이동하기 직전 목록의 주소와 검색·정렬·페이지를 다시 찾는 데 필요한 정보다. 표시 중인 데이터의 결과 출처와 별개다.

**설치 기록**: 어떤 공용 원본을 프로젝트 어디에 설치했는지와, 설치 직후의 기준본을 식별하는 정보다. 이후 프로젝트 수정과 원본 변경을 구별하는 출발점이다.

**검사 실행 기록**: 어떤 입력 상태에서 실행한 검사가 어떤 결과를 냈는지 연결하는 정보다. 설치 당시의 기준본과 현재 검사한 수정본은 서로 다를 수 있다.

**주소 검색값(`urlSearch`)**: route가 검증해 넘긴 지금 주소의 검색 값 그대로다. 기본값과 같은 칸은 빠져 있다. `useList`만 받는다.

**확정 조건(`criteria`)**: 주소 검색값에 기본값을 채운 값이다(주소 키별). 조회·다운로드·화면 부품이 읽는 조건이며, 입력만 하고 검색하지 않은 초안은 들어가지 않는다.

**조건 적용(`filtered`)**: 확정 조건에 실제로 결과를 거르는 값이 있는가다. 기본값과 다른가가 아니다: 기본값으로 걸린 값(기본 기간 등)도 조건 적용이고, 다중 선택의 전부 선택·기간 기준만 고른 상태는 조건이 아니다. 빈 결과 문구(조건 없이 0건 / 조건에 맞는 것이 0건)를 가른다.

**칸 제목·값별 문구(`title`·`valueLabels`)**: 칸 제목은 검색 칸 하나의 이름이고, 값별 문구는 선언한 값(검색 대상·기간 기준·선택지·정렬 값)마다 보일 글자다. 어느 부품이든 값별 문구는 `valueLabels` 하나로 받는다.

**일괄 작업 결과(`requestedIds`·`completedIds`·`details`)**: 요청한 행(확인창에 고정한 ID, 키트가 채운다), 실제로 처리된 행, 업무가 화면에 보일 결과다. 앞의 둘을 비교해 부분 결과를 안내한다.

**고른 값(`choice`)**: 값을 골라 바꾸는 일괄 작업에서 사용자가 고른 값이다. 확인창을 여는 순간 고정된다. 업무 결과(`details`)와 다르다.
