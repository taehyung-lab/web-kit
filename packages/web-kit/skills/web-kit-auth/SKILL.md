# 로그인 전 인증 단계

`/auth`의 순수 계산·진행 hook과 registry `auth` 복사본을 연결한다. 공개 타입은 설치된 `src/auth.ts`가 기준이다. [소비 안내](../../docs/consuming.md#복사본-적합성-검사)의 검사 설치 절차를 따른다.

## 연결 순서

조립 방식만 참고한다. 필드·기본값·문구·권한은 예시 값이며 프로젝트의 원문·결정으로 정한다.

검사 조립 예: [starter 인증 검사 화면](../../../../apps/starter/src/shared/ui/web-kit/checks/auth.page.tsx). starter 제품 로그인에는 인증 단계가 없어 제품 연결은 검사하지 않음.

1. 프로젝트가 로그인 성공 전 임시 인증 정보를 메모리에서 소유한다. 새 로그인은 새 `scope`와 새 기한을 만들고, 같은 로그인 안 방식 전환은 `scope`만 바꾸며 이메일 코드 기한은 유지한다. 새로고침 후에는 로그인부터 다시 시작한다. URL·영속 저장소에 임시 자격정보를 넣지 않는다.
2. 앱 진입점에서 `/session/idle`의 `createServerClock({ key })`를 한 번 만든다. 로그인 전 `useAuthChallenge`와 로그인 후 `createIdleTimer({ clock, ... })`에 **같은 객체**를 넘긴다. 기존 유휴 타이머 key가 `app-idle`이면 시계 key는 기존 저장 형식인 `app-idle:clock`이다. 로그인 전 응답은 `clock.observe(offsetMs)`로 관측하고 로그인 후는 기존 `idle.observe(sample)` 연결을 유지한다. offset은 서버 시각−로컬 시각(ms)이며 헤더 해석은 프로젝트 서버 계약이다.
3. `useAuthChallenge`에 `codeLength`, 절대 시각 `codeExpiresAt`·`expiresAt`·`resendAvailableAt`, `verify`·`onVerified`, 필요하면 `resend`·`onResent`를 연결한다. 기한은 같은 서버 시계 기준이다. 시간 값 기본값은 없고 전체 기한 생략은 전체 시간 정책을 끈다. 재전송 대기 생략은 별도 cooldown이 없다는 뜻이다. REF의 5분·30분은 프로젝트 값이며 키트 기본값이 아니다.
4. 요청 함수는 요청·응답 반환만 맡고 세션 저장·화면 이동 같은 성공 효과는 `onVerified`에 둔다. `onResent`에서 **성공한 현재 요청에만** 새 코드 기한과 재전송 가능 시각을 적용한다. 서버가 주지 않으면 프로젝트 시간 정책을 공유 시계 `clock.now()`에 더한다. 성공 콜백은 이동 완료까지 Promise를 반환할 수 있다. 콜백 실행 뒤 추가 비동기 효과가 있다면 프로젝트가 자기 이동 수명도 확인한다.
5. 취소·영역 이탈 또는 라우터 이동 시작에 `invalidate()`를 먼저 부른다. 화면 unmount 전 지연 구간에서도 옛 응답을 버린다. 방식 전환은 새 `scope`로도 무효화된다. 입력 값 초기화는 복사본의 key 또는 프로젝트 입력 상태로 연결한다.
6. registry `AuthCodeForm`에 모델·자리수·문구를 넘긴다. 만료 시 입력 편집은 유지하고 버튼과 Enter 제출을 막는다. 실패 값은 `model.failure`로 전달된다. 서버 오류 코드·계정 잠금·안내창 선택은 프로젝트가 해석하고, 제출을 막을 때 `blocked`를 전달한다. 등록 정보 생성·QR 해석·등록 완료 후 이동은 제품 계약이므로 프로젝트에 남긴다.

## 키트 보장

조립 방식만 참고한다. 필드·기본값·문구·권한은 예시 값이며 프로젝트의 원문·결정으로 정한다.

실행 예: [starter 단위 검사 연결](../../../../apps/starter/src/shared/ui/web-kit/checks/auth.test.tsx). 실제 인증 서버 검증은 소비 프로젝트 책임이다.

- 남은 초는 절대 기한에서 올림 계산하고 0 아래로 내려가지 않는다. 타이머가 늦어져도 다음 갱신·탭 복귀 때 현재 시각으로 다시 계산한다. 요청 직전에는 표시 tick과 무관하게 현재 시각을 검사한다.
- 코드 기한이 끝나면 확인·Enter 제출을 차단한다. 전체 기한이 끝나면 확인·재전송과 늦은 응답 적용을 차단한다. 입력은 계속 편집할 수 있다. 유효 숫자와 자리수는 요청 전에 검사한다.
- 확인·재전송은 같은 진행 관문을 사용하여 한 번에 한 요청만 실행한다. 성공 콜백이 끝날 때까지 잠금을 유지한다. 실패 후 다시 시도할 수 있다.
- 취소·scope 교체·unmount 뒤의 성공과 실패는 적용하지 않는다. 옛 요청 완료가 새 요청의 pending을 끄지 않는다. 실행 중 요청의 서버 처리를 취소한다고 보장하지는 않는다.
- 인증 단계는 세션을 생성·연장·종료하지 않는다. 시계 보정만 공유한다.

## 검사와 이전

조립 방식만 참고한다. 필드·기본값·문구·권한은 예시 값이며 프로젝트의 원문·결정으로 정한다.

브라우저 조립 예: [starter 브라우저 검사 연결](../../../../apps/starter/tests/e2e/web-kit/auth.spec.ts).

registry `auth`의 단위·브라우저 연결 파일을 실제 복사본과 함께 실행하고 `web-kit-check`를 필수 CI에 둔다. 입력을 바꾸면 `enterCode`·`readCode` 행동 어댑터만 그 모양에 맞춘다. 공통 검사는 입력 개수나 DOM 배치 대신 남은 시간·편집 값·Enter·요청 횟수·결과 적용을 관찰한다. 저장소의 한 칸/여섯 칸 검사는 모양 변경의 예이며 소비처 연결 증명을 대신하지 않는다.

기존 인증 전용 interval·재전송 pending·늦은 응답 판정을 이 hook으로 교체하고, 기존 API 요청을 순수한 요청 함수로 만든 뒤 세션 적용을 성공 콜백으로 옮긴다. 기존 `/session/idle` 사용자는 clock 생략 시 이전 API가 유지된다. 인증 전 단계도 쓰는 앱은 위의 공유 객체 연결로 이전한다.
