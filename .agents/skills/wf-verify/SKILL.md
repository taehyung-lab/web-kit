# 결과 검토

판정의 근거는 요청 원문·사용자 결정·계약과 실제 관찰이다. 구현자의 자기평가는 근거가 아니다.

## 절차

1. **원문과 대조한다.** 요청 원문과 사용자 답을 다시 읽고, 요구마다 실행한 명령과 실제 출력으로 확인한다. 바꾼 코드가 지키던 기존 보장도 같다. 확인하지 못한 것은 사유·재개 조건과 함께 미확인으로 남긴다(빼거나 낮추는 것은 사용자가 정한다).
2. **확인받지 않은 결정을 찾는다.** 결과에 들어간 동작 가운데 `wf-ask` 에서 사용자에게 보이지 않은 읽기·선택이 있으면 완료가 아니다. `wf-ask` 로 돌아가 묻는다.
3. **지도의 형식과 남은 항목을 확인한다.** `python3 .agents/skills/wf-verify/verify.py record --map <지도>`. 종료 0은 기록 형식이 맞다는 뜻이며 완료 판정이 아니다. open_decisions가 남으면 묻고 unconfirmed는 조사한다. 1·2의 결과 대조와 필요한 독립 검토까지 끝나야 완료다.
4. **독립 검토를 받는다.** AGENTS.md 기본 4가 정한 작업(사용자 요구, 검사 약화, 외부 시스템이 읽는 형식·계약 변경)은 반드시 받는다. 그 밖에는 어떤 보장이 깨질 수 있는데 직접 확인만으로 확인하기 어려울 때 골라서 받는다(그 이유를 한 줄로 밝힌다).
   1. `verify.py prepare --map <지도>` (지도가 없으면 사용자 글 그대로를 `--request <파일>`, 작업 전 커밋이 HEAD 가 아니면 `--base <커밋>`, 분석·설계 산출물이나 구현자 보고·명령·출력은 `--output <파일>`). 입력이 모자라면 미확인이다(요약으로 대신하지 않는다).
   2. `prompt_file` 을 그대로 하위 에이전트(검토자)에게 맡긴다.
   3. 검토자의 마지막 답을 고치지 않고 `verify.py finish --round <kept> --check <직접 검사 결과>` 의 표준 입력으로 넘긴다.
   4. returned 면 사유를 원문·기준과 대조해 원인이 있는 단계로 돌아간다(요구는 `wf-ask`, 설계·코드·검사는 `wf-build`). 고친 뒤 prepare 부터. incomplete 는 미완료, unverified 는 사유·재개 조건과 함께 보고한다.

## 끝 조건

1·2가 끝났고, 미정·미확인·검사 실패가 없으며, 독립 검토가 필수인 작업은 검토까지 통과했다. 그렇지 않으면 완료라 하지 않고 남은 것을 그대로 알린다.

## 검토자 기준

판정 범위는 바꾼 동작·산출물과 연결 근거가 있는 기존 보장이다. 요구의 근거는 요구 기록의 출처(원문·사용자 결정·계약·조사 사실)다. 새 요구가 있어야 성립하는 반례는 범위 밖으로 따로 적는다.
