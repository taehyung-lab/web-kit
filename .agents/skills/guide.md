# 선택 안내: 작업 지도·맥락 봉투·질문·독립 검토

AGENTS.md 의 기본 기준만으로 부족할 때 해당 절만 읽는다. 매 작업에 쓰지 않는다.

## 작업 지도: 결정·의존·완료 조건을 대화만으로 놓칠 위험이 있을 때

- 위치는 `work/<작업명>/work.md`. 사용자 몫의 미정을 묻기 전에 쓴다. 끝나면 재사용할 결정을 반영하고 지도를 정리한다.
- `## 기준`: `요청 원문`(사용자 글 그대로, 결과·범위를 바꾼 후속 글 포함)과 요구 기록 표 `ID | 요구(입력→관찰 장소→기대) | 출처·위치 | 의존 | 확인 방법 | 상태`.
  - 출처(원문·사용자 결정·계약·조사 사실)가 결과 일부만 정하면 행을 나눠 나머지를 미정으로 둔다. 예: "기존 기록 유지"는 행 보존만 정하고 충돌 기록의 확정 안내는 정하지 않는다.
  - 상태는 확정·미정(사용자 답)·미확인(조사). 미정·미확인에 의존하면 확정이 아니고, 남아 있으면 완료가 아니다(verify.py 가 검사). 확인 방법은 요구를 어기면 실패해야 한다. 범위 밖은 넣지 않는다.
- 구현 전 시나리오를 이어 본다(예: 응답 유실 → 재시도 → 조회). 목표를 깨는 순서가 확인 방법을 통과하면 표를 고친다.
- 설계(책임·변경 위치)와 실행 결과는 `## 기준` 밖에 요구 ID 로 잇는다. 사용자 결과·범위를 바꾸는 기준 수정은 확인한다.

## 맥락 봉투: 대상·근거·결정을 놓칠 위험이 있을 때 (지도의 `## 맥락`, 짧은 일은 대화 몇 줄)

- 대상(결과를 둘 저장소·경로, 커밋·변경 여부)과 근거(경로·버전·용도: 현재 결정 / 과거 비교 / 연결 예). 근거는 현재 파일과 대조한 뒤 쓴다.
- 범위 안·밖, 시나리오 전(이미 성립한 것)·행동·후(다음 단계가 받을 것), 작업·위임별 작성권(쓰는 경로).
- 시작·대상 변경·재개·정정 때 `python3 .agents/skills/wf-context/context.py inspect`(경로·커밋·변경·키트 버전)로 바뀐 항목만 고친다. 새 턴이라는 이유만으로 다시 조사하지 않는다. 비밀값·env 내용은 적지 않는다.
- 위임·검토에 봉투, 인계에는 증거·남은 일도 넣고 수신을 확인한다. 독립 분석 단계는 원문·봉투·근거만, 교차 리뷰 단계는 상대 산출물까지 읽는다고 적는다.

## 질문: 사용자 몫의 미정이 남았을 때

목표·사용 상황·권한·범위·정책이 미정이라 결과가 갈리면(미정 행) 근거가 정한 것과 남은 선택, 결과 차이, 추천 이유를 붙여 묻는다. 질문 전제는 현재 대상·환경에 둔다. 앞 답에 기대는 질문은 답 뒤로 미루고 독립 질문은 묶는다.

## 독립 검토: 직접 확인만으로 확인하기 어려운 공백이 있을 때

고르는 이유를 한 줄로 밝힌다: 어떤 보장이 깨질 수 있고 직접 검사로 무엇을 확인하기 어려운가. 사용자 요구, 검사를 지우·건너뛰·약화하는 기준 변경은 반드시 받는다.

1. `python3 .agents/skills/wf-verify/verify.py prepare --map work/<작업명>/work.md` (지도가 없으면 사용자 글 그대로를 `--request <파일>`, 작업 전 커밋이 HEAD 가 아니면 `--base <커밋>`, 분석·설계 산출물이나 기준이 묻는 구현자 보고·명령·출력은 `--output <파일>`). 입력이 모자라면 미확인이다(요약으로 대신하지 않는다).
2. `prompt_file` 을 그대로 하위 에이전트(검토자)에게 맡긴다.
3. 검토자의 마지막 답을 고치지 않고 `verify.py finish --round <kept> --check <직접 검사 결과 PASS|FAIL|REVIEW>` 의 표준 입력으로 넘긴다. 전체 완료는 completion=verified 뿐이다(waiting-user 면 묻는다).
4. returned 면 사유를 원문·기준과 대조해 원인 자리로 돌아간다(요구 정의·설계·코드·검사, 사용자 몫이면 질문). 고친 뒤 prepare 부터. incomplete 는 미완료, unverified 는 사유·재개 조건과 함께 보고한다.

검토자 기준: 판정 범위는 바꾼 동작·산출물과 연결 근거가 있는 기존 보장이다. 요구의 근거는 요구 기록의 출처(원문·사용자 결정·계약·조사 사실)이고 구현자의 자기평가는 근거가 아니다. 새 요구가 있어야 성립하는 반례는 범위 밖으로 따로 적는다.
