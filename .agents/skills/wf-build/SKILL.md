# 구현

확인된 요구를 하나씩 만든다. 기대값은 요구에서 나오고, 구현을 보고 정하지 않는다.

## 절차

1. **요구마다 기대값을 정한다.** 입력 → 관찰 장소 → 기대. 관찰 장소는 사용자가 쓰는 경로(공개 명령·화면·요청·저장된 값)다. 지도가 있으면 요구 기록 표의 행이 이것이다.
2. **그 기대값을 보는 검사를 먼저 쓰고 실패를 본다.** 실패하지 않으면 검사가 요구를 보지 않는 것이니 검사를 고친다. 내부 호출만 보는 검사로 닫지 않는다.
3. **그 검사가 통과할 만큼만 구현하고 전체 검사를 돌린다.** 통과하면 다음 요구로 간다. 요청 밖의 동작·표현은 그대로 둔다.
4. **요구들을 사용 흐름으로 이어 본다.** 예: 응답 유실 → 다시 시도 → 조회. 순서·동시 실행·이미 쌓인 자료가 요구를 깨는 경우를 실제로 돌려 보고, 깨지면 2로 돌아가 검사를 더한다.
5. **새 선택을 만나면 정하지 않는다.** 만들다가 사용자가 보는 결과가 갈리는데 확인받지 않은 읽기·선택이 나오면 `wf-ask` 로 돌아간다.

## 끝 조건

요구마다 먼저 실패했던 검사가 통과하고, 바꾼 코드가 지키던 기존 검사가 통과한다. 실행한 명령과 실제 출력을 요구별로 남긴다(지도가 있으면 `## 기준` 밖에 요구 ID 로 잇는다).
