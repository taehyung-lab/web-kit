# 0010. 실행 수명: 요청 결과의 주인은 방문과 로그인이다

- 출처: 2026-11-24 사용자 결정(소비 프로젝트 dt-admin의 "요청의 결과는 그 요청을 시작한 페이지 방문의 것", "모든 공용 창·안내는 주소가 바뀌면 닫힌다", "떠난 뒤 실패한 시킨 일은 한 번 알린다")과 키트/프로젝트 역할 경계 결정("키트는 프로젝트 기준을 모르고, 연결은 한 번").
- 상태: 채택. 사용 보장 정본은 [web-kit-http](../../packages/web-kit/skills/web-kit-http/SKILL.md)의 「실행 수명」과 각 기능 스킬이다.

## 결정

요청 하나의 결과를 누구에게 전달할지를 키트가 판정한다.

| 주인 | 그의 것 | 주인이 바뀌면 |
| --- | --- | --- |
| 방문(앱이 `leave`로 알린다) | 화면에 그려지는 것: 조회 결과, 열린 확인·거절·실패 안내, 완료 처리(onSaved·onSuccess·onCompleted) | 전달하지 않는다. 조회는 취소하고 오류 상태를 지운다 |
| 로그인(세션 세대) | 사용자가 시킨 일(쓰기·파일)의 결과와 그 실패 알림 | 어디에도 전달하지 않는다 |

키트가 모르는 것은 둘이고, 앱이 한 번씩 준다.

- **방문이 무엇인가**: 주소·탭·창 가운데 무엇이 바뀌면 새 방문인지는 제품 선택이다. 앱이 `lifetime.leave()`·`arrive()`를 부른다.
- **실패를 어떻게 보일까**: 창·토스트·문구는 제품 선택이다. 키트는 실패가 난 자리(page·detail·action·download)와 그 화면이 아직 보이는지(here)만 알려 주고, 앱이 `'handled'`(직접 알렸다) 또는 `'local'`(그 자리에 둔다)로 답한다.

## 이유

- 이전에는 "부품이 내려가면 버린다"가 유일한 수명이었다. 주소가 바뀌어도 같은 부품을 이어 쓰는 화면(검색 조건을 자기 상태로 쓰는 목록)과, 새 화면이 그려지기 전에 도착한 응답에서 어긋났다. 소비 프로젝트가 저장·확인창·목록·다운로드·단건 hook 다섯 개를 모두 감싸고 키트 hook 직접 사용을 lint로 막아야 했다.
- 같은 감싸기는 다음 프로젝트도 다시 쓰게 된다. 순서·수명·경쟁의 판정은 제품과 무관하므로 키트가 맡는다.
- 앱이 맡은 실패를 그 자리에 다시 그리지 않으려고 소비 프로젝트가 실패 객체에 표시를 붙이고 문구 함수가 `null`을 돌려주던 장치를, 키트가 답(`'handled'`)을 직접 받아 대체한다. 확인창은 닫히고, 폼은 입력을 둔 채 실패 줄을 만들지 않으며, 일괄 작업은 선택을 둔 채 끝난다.

## 검토한 대안

- **실행마다 취소 신호를 넘겨 떠나면 요청을 끊기**: 이미 보낸 쓰기는 서버에서 취소되지 않는다. 끊으면 결과만 모르게 된다. 쓰기는 끝까지 가고 화면 효과만 거른다.
- **쓰기 실행 중 이탈을 모두 막기**: 폼의 저장 중 차단(FormGuard)은 그대로 둔다. 확인창·일괄 작업까지 넓히면 실행이 스스로 하는 이동(삭제 뒤 목록 이동)과 앱의 강제 이동(권한 상실·세션 종료)을 다시 예외로 풀어야 하고, 로그인 교체 때문에 실행별 판정은 어차피 남는다.
- **조회 키에 방문 번호를 넣어 데이터까지 방문별로 나누기**: 정상 캐시 재사용을 깬다. 진행 중 조회 취소와 오류 상태 정리로 같은 결과를 얻는다.

## 경계

- 연결하지 않은 앱은 이전과 같다: 방문은 바뀌지 않고 실패는 그 자리에 남는다.
- 로그인 없이 시작한 실행(로그인 요청)은 그 실행이 세션을 여는 것이라, 시작한 화면에 있는 동안은 로그인으로 가르지 않는다. 화면을 떠난 로그인 시도의 늦은 결과는 다음 로그인에 넘기지 않는다.
- `leave`는 이동이 시작됐다는 뜻이고 이동은 실패할 수 있다. 그래서 실행 중인 확인·완료 처리는 방문 변경으로 지우지 않고 실행이 끝날 때 스스로 정리한다: 요청 단계의 결과는 시작한 방문에만 전달하고, 완료 처리의 실패(이동 실패)는 부품이 남아 있으면 그 자리에서 다시 시도하게 한다.
- 파일처럼 화면 밖에 남는 결과는 키트가 대신 버릴 수 없다. 다운로드 실행 함수에 로그인 종료 신호(`step.signal`)를 주고, 쓰기 직전 확인은 소비자가 한다.
- 탭을 닫거나 새로고침한 뒤 서버가 쓰기를 어디까지 처리했는지는 키트가 보장하지 않는다.
