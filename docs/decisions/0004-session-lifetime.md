# 0004. 세션 수명과 유휴 정책 분리

- 결정권자: 사용자. 출처: 2026-10-23 세션 사용자 결정, 2026-10-27 세션 설계, 2026-10-29 멈춤·재개 사용자 결정, 2026-10-30 정책 분리 사용자 승인. 저장소 밖 인계 자료는 경위이며 배포 근거로 삼지 않는다.
- 상태: 결정 통합(2026-10-30). 정책 분리 구현의 최종 독립 판정은 별도다. 보장·이전 입력은 [web-kit-http](../../packages/web-kit/skills/web-kit-http/SKILL.md)가 정본이다.

## 세션 수명과 종료

요청 전송과 세션 수명은 키트 책임이되 interface와 판정 소유자를 구분한다. 세션 교체 뒤 옛 결과의 저장·재전송·상태 반영을 차단하고 이전 데이터 노출을 막는다. 서버에서 이미 실행된 쓰기의 취소나 브라우저 쿠키 격리까지 뜻하지 않는다([외부 계약 E3](0003-request-response-failure.md#미확인-외부-계약)).

종료는 자격증명을 잡은 뒤 저장값 삭제 → 정리 구독 → 앱 안내·이동 → 서버 signOut 순서로 한 곳에서 정한다. 정리 구독을 먼저 하여 이전 사용자 캐시가 남은 채 안내하지 않게 한다. 로컬·유휴 종료만 서버 로그아웃을 보내며 서버·다른 탭 종료는 다시 보내지 않는다. 로컬 종료를 먼저 끝내 서버 응답 지연이 로그아웃을 막지 않게 하고 서버 실패가 로컬 종료를 되돌리지 않게 한다.

## 유휴 장치와 정책 경계

- `/session/idle`은 명시적으로 만들고 시작한 앱만 사용한다. 목록·폼·단건 상태가 이 기능을 암묵적으로 import하지 않게 하여 사용하지 않는 앱에 정책을 강제하지 않는다.
- 활동 감지·간격 제한은 별도 선택 부품, 세션에 묶인 시도·마감 저장과 탭 병합은 수명 장치에 둔다. 활동 부품은 저장 형식을 모른다. 임시 마감·채택할 응답·재개 유예 길이·경고 닫음·재노출·문구용 세션 길이는 프로젝트가 소유한다.
- 자동 첫 표본·고정 유예·자동 임시 마감을 끄는 옵션을 덧붙이지 않고 원래 정책 자리를 제거한다. 실제 서버 계약 없는 starter 기본 화면에도 새 정책을 가정하지 않는다.
- 0초에 자기 탭 진행 중 연장을 기다릴지는 같은 만료 기능의 필수 선택이며 기본값은 없다. 다른 탭의 종료가 우선할 수 있다. 요청·마감 채택·경고 해소 사실을 구분하고 화면의 성공 판정은 대신하지 않는다.
- 사용자 결정(2026-10-30): “같은 세션의 더 늦은 서버 마감만”. 요청 순서보다 마감 크기를 우선하고 동시 저장의 긴 마감 유실을 막는다. 로컬 임시·유예와 서버 승인을 구분한다. 이는 클라이언트 채택 승인이지 서버가 단축하지 않는다는 확인이 아니다.
- 사용자 결정(2026-10-30): 경고 닫음 상태를 프로젝트 UI로 옮긴다. 보이는 동작의 보존은 각 프로젝트 이전에서 확인한다.

### 일반 API 응답으로 연장하지 않은 이유

사용자 결정(2026-10-29): 일반 요청 응답을 관측한 것만으로 마감을 늘리지 않는다. 미리 불러오는 요청 때문에 사람이 없어도 연장되던 문제를 막기 위한 선택이다. 연장 여부·간격·버튼 정책은 프로젝트 입력이다.

## 탭·시계·멈춤을 고른 이유

- 대표 탭은 Web Locks로 고른다. 심장박동·선거·사전순 수렴보다 닫힘 때 잠금 해제가 단순하다. 대표만 제때 끝내면 복구 유예는 쓰지 않는다. 잠금 보유 탭이 정지한 경우를 위해 마감 뒤 비대표 5초 복구 장치를 유지한다.
- Worker tick과 화면 복귀·저장 변경 때 즉시 재판정한다. Worker를 못 만들면 setInterval로 대체한다. 같은 백그라운드 제한을 받는 별도 setTimeout 알람은 더하지 않는다. 경고 UI 열림이 만료 판단을 소유하지 않는다.
- 멈춤은 탭 단위이며 대표를 내놓는다. 다른 탭 종료는 적용한다. 탭 사이 멈춤을 공유하면 죽은 탭의 멈춤을 풀 수단이 없기 때문이다.
- 재개는 서버 연장을 한 번 보내고 진행 중 호출은 합류한다. 활동 간격과 별개인 사용자 동작 한 번의 ping이므로 간격 제한으로 재개 자체를 막지 않는다. 일반 응답 마감으로 재개하는 두 번째 경로는 두지 않는다.
- 재개 대기 중 다시 멈추면 마지막 화면 요청이 이긴다. 받은 서버 마감은 저장하되 멈춤을 유지하여 다른 탭·서버와 어긋나지 않게 한다. 시작 전 멈춤도 재개 판정에 맡긴다. 고정 재개 유예와 단일 성공 정의는 정책 분리 결정이 대체했다.

## 미확인과 재검토 조건

- [E1–E3](0003-request-response-failure.md#미확인-외부-계약)는 보류한다.
- 저장 불가·Web Locks/Worker 없는 환경의 탭 단일성과 보장을 확대하지 않는다. Web Locks가 없으면 모든 탭이 대표처럼 동작할 수 있다.
- 실제 서버 TTL·마감 단축 가능성과 채택 규칙의 호환성은 서버별 확인이 필요하다. 비대표 5초 복구와 각 프로젝트의 0초·수동 연장 정책이 맞는지도 실제 이전에서 확인한다.
- 서버가 유휴 마감을 소유하게 되면 마감 채택을 재검토한다. 경고를 대표 대신 지금 보는 탭에 띄워야 하는 요구가 확인되면 대표 선택 기준을 재검토한다.
