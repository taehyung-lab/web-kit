# 0004. 세션 유휴 타이머를 키트로 옮기고, 종료 순서를 세션 한 곳에서 정한다

- 상태: 채택 (2026-10-27, 3단계 설계). 결정권자는 사용자이며 [0003](0003-web-kit-3-redesign.md) §3·§4·§6 범위 안의 해법 선택이다.
- 근거 자료: DT v2 `fb91fa5`(`apps/admin/src/app/session/`, `packages/api-client/src/web-kit.ts`·`http/session-*.ts`, `public/session-timeout-popup.*`, DT 결정 0001·0003), 레퍼런스 `89f8f655`(`src/api/http/reissue.ts`·`credential.ts`), web-kit `5e86d4e`(`session.ts`·`http.ts`·`query.ts`·`browser-session-store.ts`).
- 보장 내용의 정본은 `packages/web-kit/skills/web-kit-http`다. 여기에는 무엇을 골랐는지와 이유만 둔다.

## 맥락

0003은 세션의 유휴 마감·경고·연장·종료와 종료 시 캐시 정리 순서를 키트 책임으로 정했다. 현재 그 기능은 DT에만 있고(테스트 포함 약 6.5천 줄), 레퍼런스에는 없다. 키트에는 세대·저장·탭 동기화·재발급 합류만 있다.

DT 구현은 1.5에서 실측한 결함을 하나씩 막아 온 결과라 동작 근거로는 정확하다. 그러나 구조의 상당 부분이 다음 문제를 우회하는 장치다.

- 탭 마스터를 localStorage 심장박동·선거·사전순 승자 규칙으로 정한다. 탭이 죽으면 심장박동이 멈출 때까지 기다려야 하고, 동시 등극을 다시 수렴시키는 코드가 따로 있다.
- 경고 팝업이 API를 부르지 못해 localStorage 액션 봉투·소유 탭 ID·고아 액션 수거·경고 소유 키를 둔다.
- UI가 만료 판단의 일부를 쥐고 있어(팝업·대체 모달이 열려 있으면 만료 금지) UI가 죽으면 세션이 끝나지 않았고, 이를 막는 15초 감시가 또 있다.
- 종료 신호를 BroadcastChannel·storage 신호 키·세션 저장 세 경로로 보낸다.
- 마감 표본이 세션 ID와 묶여 있지 않아 "새 로그인은 이전 표본을 무시한다"를 시작 분기마다 따로 지킨다.

## 결정

### 1. 유휴 타이머는 `/session/idle` 입구 하나로 둔다

- 앱이 `createIdleTimer`를 만들고 `start()`를 불러야만 동작한다. 만들지 않은 앱(starter)에는 결과물에 들어가지 않는다. 목록·폼·record는 이 입구를 import하지 않는다(경계 검사로 막는다).
- 프로젝트가 넘기는 값: 시간 정책(마감 길이·경고 구간·활동 연장 간격), 저장 key, 서버 연장 함수, 응답에서 읽은 서버 시각 표본. 표본의 헤더 형식(`X-Session-Expires`·`Date`)은 서버 계약이라 프로젝트 adapter가 숫자로 바꿔 넘긴다.
- 키트가 내놓는 것: 상태(단계 `inactive`·`active`·`warning`, 마감, 세션 길이, 대표 탭 여부, 연장 중, 경고 닫음)와 남은 시간을 **따로** 읽는 함수. 상태 구독은 단계가 바뀔 때만 알리고, 남은 시간 표시는 매초 구독을 따로 쓴다. 그래서 만료 판단만 쓰는 앱과 카운트다운을 그리는 화면이 서로를 끌어오지 않는다. React hook은 두지 않는다(`useSyncExternalStore`에 바로 넘길 수 있는 모양만 맞춘다).
- 동작 분기 옵션은 두지 않는다. 경고 디자인(팝업 창·대체 모달·OS 알림·탭 제목)은 프로젝트가 상태를 보고 그린다.

### 2. 마감은 로그인과 명시적 연장만 바꾼다 (DT 결정 0001 그대로)

- 일반 응답의 표본은 시계 보정에만 쓴다. 재발급 성공도 마감을 바꾸지 않는다.
- 예외는 로그인 직후 한 번이다. 로그인 때 로컬 시계로 임시 마감을 잡고, 로그인 뒤에 보낸 첫 응답의 서버 마감으로 확정한다(DT 「로그인 시드 창」).
- 경고 구간 밖의 사용자 조작(click·mousedown·keydown·wheel·touchstart·popstate, 문서가 보이고 포커스가 있을 때만)은 활동 연장 간격마다 서버 연장을 부른다. 경고 구간 안에서는 조작이 연장하지 않고, 연장 수단은 `extend()`(연장 버튼)뿐이다. 판정 기준은 UI 열림이 아니라 남은 시간이다.
- 연장 성공은 HTTP 성공이 아니라 "서버가 준 마감을 채택했고 남은 시간이 경고 구간을 벗어났다"이다. 아니면 실패로 돌려주고 경고를 유지한다.
- 마감 표본은 세션 ID와 함께 저장한다. 다른 세션 ID의 표본, 이전 표본보다 먼저 보낸 요청의 표본(보낸 시각 기준)은 채택하지 않는다. 그래서 이전 로그인에서 시작한 연장 응답이 새 로그인의 마감을 바꾸는 경로가 구조적으로 없다.
- 이전 형식(`zs-admin-serverTimeSample` v2)은 읽지 않는다. DT v2는 아직 배포 전이라 이전할 활성 세션이 없다.

### 3. 대표 탭은 Web Locks로 고른다

| 방식 | 판단 |
|---|---|
| DT: localStorage 심장박동 + 선거 + 사전순 승자 | 탭이 죽은 뒤 최대 60초(경고 중 5초) 동안 대표가 없다. 동시 등극 수렴·고아 수거 코드가 필요하다. |
| 모든 탭이 각자 경고·만료 | 경고 팝업과 만료 안내가 탭 수만큼 뜬다. |
| **Web Locks 보유 탭이 대표(채택)** | 탭이 닫히거나 죽으면 브라우저가 잠금을 풀고 다음 대기 탭이 즉시 대표가 된다. 키트는 이미 재발급 직렬화에 Web Locks를 쓴다. |

- 대표 탭만 경고를 소유하고 마감에 세션을 끝낸다. 나머지 탭은 같은 저장 마감으로 단계를 계산하고(제목 표시 등에 쓸 수 있다) 마감에 바로 끝내지 않으며, 대표가 끝낸 결과를 다른 탭 종료로 받는다. 다만 마감 뒤 5초가 지나도 세션이 끝나지 않았으면 스스로 끝낸다. 대표 탭이 잠금을 쥔 채 멈추면(백그라운드 정지·디버거 등) 잠금이 풀리지 않아 다음 탭이 대표가 되지 못하고, 그러면 만료된 세션이 어느 탭에서도 끝나지 않기 때문이다. 대표가 제때 끝내면 이 유예는 쓰이지 않는다.
- 활동 연장은 조작이 일어난 탭이 직접 부른다(마스터 중계 없음). 조작은 포커스가 있는 탭에서만 생기므로 동시에 여러 탭이 부를 일이 드물고, 저장된 마지막 연장 시각으로 간격을 탭 사이에서 공유한다.
- Web Locks가 없는 환경에서는 모든 탭이 대표처럼 동작한다(경고가 탭마다 뜰 수 있다). 0003 §6처럼 이 환경의 단일성은 검증 전에는 약속하지 않는다.

### 4. 만료 판단은 시간만 본다

- 대표 탭에서 남은 시간이 0 이하이면 끝낸다. 연장 요청이 진행 중이면 그 결과를 본 뒤 다시 판단한다. 경고 UI가 열려 있다는 사실은 만료를 막지 않는다(UI는 상태를 따라 닫힌다). 그래서 DT의 만료 금지 가드와 15초 감시가 필요 없다.
- 시계는 Worker 1초 tick을 쓰고, 만들 수 없으면 setInterval로 내려간다. 화면 복귀(visibilitychange·pageshow)와 다른 탭의 저장 변경 때 즉시 다시 판단한다. DT의 별도 절대시각 알람은 두지 않는다. Worker가 없을 때의 setTimeout은 setInterval과 같은 백그라운드 제한을 받아 더하는 것이 없기 때문이다.
- `start()`는 이미 끝난 세션(이 세션 ID의 마감이 없거나 지남)을 그 자리에서 동기적으로 끝낸다. 라우터를 만들기 전에 부르면 DT 부트 게이트를 대신한다.
- 경고 구간에서 사용자가 닫으면 대기 상태가 되어 다시 띄우지 않는다. 경고 구간을 벗어나거나 문서가 다시 보이게 되면 풀린다(DT FR-9·E55-R2).

### 5. 종료 순서는 세션이 정한다

- 세션 종료 사유에 `idle`을 더한다: `local`(이 탭 로그아웃), `idle`(유휴 마감), `other-tab`, `server`(인증 계약).
- `createSession`이 선택 입력 `signOut(credentials)`를 받는다. `local`·`idle` 종료에서 키트가 자격증명을 먼저 잡아 두고 → 저장값을 지우고 → 정리 구독(쿼리 캐시 비움)을 부르고 → 앱 구독(안내·이동)을 부른 다음 → `signOut`을 한 번 보낸다. 실패는 삼키며 로컬 종료를 되돌리지 않는다. `server`·`other-tab` 종료에서는 보내지 않는다(서버 세션이 이미 무효이거나 끝낸 탭이 보냈다).
- 정리 구독은 앱 구독보다 항상 먼저 돈다. 지금은 구독 등록 순서에 기대고 있어, 앱이 먼저 구독하면 이전 사용자 캐시가 남은 채 안내가 뜰 수 있다.
- DT 1.5의 로그아웃은 서버 응답을 기다린 뒤 로컬을 지웠다. 서버가 응답하지 않으면 timeout(60초)까지 로그아웃되지 않는다. 키트 기존 보장(로컬 먼저)과 starter 동작에 맞춰 로컬을 먼저 끝낸다. 화면에서는 로그아웃 버튼을 누르면 서버 응답을 기다리지 않고 바로 로그인 화면으로 간다.

### 6. DT에 남기는 것과 지우는 것

- 남김(경고 디자인, 프로젝트 책임): 팝업 창과 그 정적 파일, 팝업이 막혔거나 문서가 뜨지 않았을 때의 대체 모달, 만료 모달, OS 알림과 권한 요청, 탭 제목 표시, 잔여 시간 배지, 만료 후 이동.
- 팝업과 대표 탭은 `postMessage`로 직접 주고받는다(대표 탭이 남은 시간·문구를 보내고, 팝업이 연장·로그아웃을 보낸다. 출처와 창을 확인한다). 그래서 액션 봉투·경고 소유 키·고아 수거가 필요 없다. 팝업은 대표 탭이 사라지면 스스로 닫는 기존 동작을 유지한다.
- 지움(키트로 옮김): 세션 코어 전체(`app/session/core/*`의 마감·시계·마스터·채널·알람·가드·부트 게이트), 세션 시각 이벤트와 저장 키(`session-time-sync`·`session:reset`·`zs-admin-sessionExpires`·`clockOffset`·`serverTimeSample`), 종료 신호 키.
- 지움(쓰는 곳 없음): `isUserPresent`(폴링 게이트용으로 만들었지만 읽는 코드가 없다), 테스트 전용 세션 길이 분기(`TEST_DURATION_MS`와 활성 탭 판정). 테스트 세션 길이는 정책 값으로 넘긴다.

## 레퍼런스와의 비교

| 항목 | 레퍼런스 | 키트 (채택) |
|---|---|---|
| 세션 구분 | 자격증명이 지워진 횟수. 지우지 않고 다른 계정으로 바뀐 경우를 구분하지 못한다(파일 주석에 명시). | 세션 ID와 세대. 교체도 새 세대다. |
| 재발급 합류·탭 직렬화 | Web Locks + 탭 안 단일 비행 | 같다. lock 안에서 저장값을 다시 읽는 것도 같다. |
| 유휴 마감 | 없음 | 이 결정 |

## 미확인

- E1–E3(0001)은 그대로 보류한다.
- 서버가 모든 인증 요청으로 세션 TTL을 늘린다는 DT 실측(2026-08-25·09-01)은 DT 서버의 사실이다. 키트는 일반 응답으로 마감을 바꾸지 않을 뿐 서버 TTL을 가정하지 않는다.
- Web Locks가 없는 브라우저에서의 탭 간 단일성.

## 재검토 조건

- 서버가 유휴 마감을 소유하게 되면(DT 결정 0001의 재검토 조건) 마감 채택 규칙을 다시 본다.
- 두 번째 소비자가 경고를 대표 탭이 아닌 "지금 보고 있는 탭"에 띄워야 하면 대표 선택 기준을 다시 본다.
