## 공개 입구와 중복의 판단

패키지 제품 실행 코드가 화면 배치·스타일·복사본 구현을 import하지 않는 것을 경계로 삼는다. 상태 전달 Provider의 JSX와 검사 전용 렌더링은 구분하여 허용한다. Base UI 의존 제거와 시각 UI 제거는 따로 판단한다.

옮긴 UI 입구를 같은 이름의 배치 없는 입구로 남기지 않는다. `/filter`는 제거하고 순수 계산은 루트, 표현은 registry에 둔다. 루트와 책임별 입구가 같은 구현을 재노출하는 것은 새 소유자를 만들지 않으므로 허용한다. 선택 검색·값 연결은 `/choice`, 확인 수명은 `/dialog`로 구분하고 목록과 폼 사이 의존을 만들지 않는다. 현재 입구 목록은 package.json exports가 정본이다.

같은 leaf 순회·부모 일부 선택 계산, 글자 수 증가 판정, 참조 확인부터 값 적용까지의 순서, 목록 빈 값 변환은 책임별 한 구현을 쓴다. 반면 `serializeSpringParams`와 `serializeFlatListParams`는 중첩 값 계약이 달라 합치지 않는다. 필터의 빈 배열=전체와 폼의 명시적 leaf 선택도 서로 다른 의미다([목록·선택 결정](0006-list-choice-permission.md)).

## 부품을 고른 이유

- context 부품은 위치를 바꿀 때 같은 배선을 반복하지 않게 한다. render prop만 강제하면 배치가 한 함수에 갇힌다.
- 단순 table을 기본으로 하고 가상화는 선택적으로 쓴다. 정렬·선택·상태는 목록이 이미 소유하므로 별도 Table 라이브러리를 필수 peer로 늘리지 않는다(구현 선택).
- 목록 일부 선택은 Base UI Checkbox, 폼 단일 체크는 네이티브 input을 쓴다. 폼의 라벨 클릭·제출 값·접근 가능한 이름 연결을 단순하게 유지한다(구현 선택).
