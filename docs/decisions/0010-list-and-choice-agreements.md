## 공용성과 사용 방식 — 2026-10-28 추가 합의

공용 동작의 기준은 특정 소비 프로젝트가 아니다. 소비 구현은 근거 칸에서 비교하며, 좋은 동작을 골라 결합하고 결함·업무 정책·프로젝트 의존성은 옮기지 않는다. 아래 합의는 방향이며, 구현 완료를 뜻하지 않는다.

## 맥락

키트는 목록·저장 과정에서 입력과 결과를 보호한다. 검색 확정, URL 복구, 서버 선택지 URL 확인(이전 상위 조건의 늦은 응답 무시 포함), 선택 실행, 저장 잠금이 테스트로 보장된다.

부족한 것은 두 가지다. 첫째, **화면 부품**이다. 크기 선택이 페이지 이동 안에 묶여 있고, 번호 페이지 이동·정렬 드롭다운·건수가 없다. 둘째, **새 공통 동작**이다. 칸 자리의 선택지 상태 처리, 하위 칸 비우기, 폼 안 참조, 팝업에서 부모 값으로 넘기기, 업로드 단계, 저장 방식 두 가지, 배열 행 정체성이 없다. 둘은 작업 규모가 다르므로 아래 표에서 「종류」로 구분한다.

DT·레퍼런스에 비슷한 부품이 있지만 그대로 가져올 수 없는 경우가 많다. 3.x의 Base UI 기반 패키지 UI 소유·배포 결정은 4.0부터 [0011](0011-web-kit-4-ui-distribution.md)이 대체한다. 당시 비교에서 DT `SearchSelect`는 Radix Popover와 `cmdk`를 쓰고, 레퍼런스 `SectionCard`는 레퍼런스의 i18n·아이콘·Accordion을 쓴다. 그래서 「근거」 칸은 **가져올 것(규칙·테스트 사례)**과 **다시 만들 것(코드)**을 나눠 적는다.

## 표 읽는 법

- **종류**
  - 모양: 기존 상태를 그대로 쓰는 표현만 추가한다.
  - 새 동작: 상태·수명·오류 처리 설계가 필요하다.
  - 이미 있음: 키트에 이미 보장되어 있어 할 일이 없거나 표현만 연결한다.
- **상태**
  - 합의: 2026-10-28 사용자 결정이다.
  - 화면 원문: 사용자와 따로 논의하지 않았고, 소비 프로젝트 화면에서 여러 번 반복되는 형태를 공용으로 옮긴 것이다.
  - 작성자 결정: 내부 구현 선택이라 작성자가 정했다. 근거가 있으면 함께 적는다.
  - 미정: 아래 「미정」 절에 있다.
- **완료 반례**: 이 중 하나라도 관찰되면 그 항목은 미완료다. 관찰은 화면·URL·요청으로 한다. 반례 속 예시 값은 설명용이다.

- **숨긴 조건부 칸의 값**: 숨기면 검증·제출에서 빼고, 다시 보이면 값을 되살리는 방식을 작성자가 추천했다. 사용자 결정 전이다.
- **가지 값을 따로 저장해야 하는 소비처**: 1-2는 맨 아래 항목만 값으로 둔다. 가지(그룹) 자체를 값으로 저장해야 하는 경우가 확인되면 이 규칙을 다시 본다.
- **업로드 흐름(5-9)의 설계**: 단계별 상태와 취소·재시도 규칙.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 선택 변형마다 부품·옵션 추가(그룹 헤더 체크 여부, 전체 칸 여부 등) | 깊이·모양이 늘 때마다 규칙이 는다. "전체"를 뿌리로 보면 옵션이 필요 없다 |
| 모양마다 칸(`List.MultiDropdown`, `List.CheckTree`…) | 모양 수 × 목록·폼만큼 칸이 생기고, 모양을 바꾸면 연결 코드를 다시 쓴다 |
| 선택 값을 그룹별 객체로(`{그룹: [항목]}`) | 주소 저장·전체 규칙·잘못된 값 복구를 이 모양 전용으로 다시 만들어야 하고, 그룹 없는 칸과 모양이 달라진다 |
| 화면이 `useQuery`로 선택지를 받아 칸에 넘김(지금) | 선언과 화면 두 곳을 맞춰야 하고, 실패 표시가 화면마다 갈라진다(DT 네 가지) |
| 서버 검색은 화면마다 직접 | 늦은 응답 버리기를 화면마다 다시 챙긴다 |
| DT·레퍼런스 부품 코드를 그대로 이식 | 의존(Radix·cmdk·레퍼런스 i18n·아이콘)이 당시 Base UI 선택과 다르다. 규칙·테스트만 가져온다 |
| 큰 폼 [저장]도 필수가 비면 끄기 | 어느 구역의 무엇이 비었는지 찾을 수 없다 |
| 모든 버튼을 늘 켜고 누르면 오류(이전 키트 방식) | 목록·작은 창은 끄는 쪽을 사용자가 골랐다 |
| 결과 탭이 필터 값을 넘겨받음 | 사용자가 탭마다 독립을 골랐다 |
| 참조 원본 삭제를 한 방식으로 고정 | 프로젝트가 관계마다 다르게 정할 수 있어 값으로 받는다 |

## 적용과 후속 작업

현재 변경·검사 순서는 [유지보수](../maintaining.md)를 따른다. 3.0 단계별 작업 배정은 Git 이력에 남긴다. 이 문서의 작성자 제안·미정은 구현 사실만으로 사용자 합의로 바꾸지 않는다. 후속 결정은 해당 항목의 근거를 대조하고, 동작 보장과 스킬·검사는 같은 변경에서 맞춘다.
