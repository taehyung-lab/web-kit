## 목록 상태와 조립

- 검색 선언부터 선택까지 같은 상태 소유자가 맡는다. 기간 검증·URL 복구가 UI 교체·숨김으로 사라지지 않게 한다. 맞지 않는 기간은 검색 전체를 막지 않고 그 쌍만 기본값으로 돌린다(2026-10-28 사용자 확인).
- 사용자 원문(2026-10-26): “기간 뿐만 아니라 없는 타입이 들어온다거나 api를 통해 받은 옵션에서도 없으면 기본값으로”. 선택지 query와 URL 확인이 같은 선언을 읽게 하여 취소·재시도·배열 복구가 갈라지지 않게 한다.
- 정렬 첫 방향 `sortFirst`는 화면 값이다. URL 표현·필드 encode·묶음 valid·보기 key도 선언에 두고 진입 주소를 정규 표현으로 replace한다. Router가 스스로 진입 주소를 고치지 않기 때문이다.
- 필터→요약→도구줄→표→페이지 이동은 일반 부품으로 조립하고 검색 모델·열·배치를 책임별로 나눈다. 직접 그리는 글자·숫자 칸도 기간·검색어·선택 칸과 같은 값·필수·검증 연결을 쓴다.
- 결과 탭은 URL이 따로인 별개 목록으로 필터 값을 공유하지 않는다. 상세검색은 확정 상세 값·초기화·오류 사건으로 열림을 판단한다. 일시 재조회 실패는 이전 결과를 유지하며 실패를 알린다(2026-10-28 사용자 승인).
- 다운로드는 누른 순간 확정 조건·선택 ID를 고정하고 진행·실패·차단은 키트, 요청 변환·파일명·저장·암호 안내는 프로젝트가 맡는다. 렌더 시점 대상을 잡으면 이후 조건·선택 변경에 실행이 흔들린다.
- 사용자 검색 실행과 배경 재조회를 구분하여 상태가 실행을 추적한다(2026-10-30 “1·2·3번 묶어서 rc.3로 진행”). URL만으로는 같은 조건 재검색의 이전 응답·선택 수명을 식별하지 못했기 때문이다.

## 선택 칸과 검색어

- 선택지는 깊이 제한 없는 트리 하나로 두고 전체는 뿌리, 그룹 전체는 그 가지 자신으로 표현한다. 다중 값은 leaf ID 목록, 단일 값은 leaf 하나다. 가지 ID 저장을 모양 옵션으로 넣지 않는다(2026-10-28 선택 칸 1-1~1-3).
- 일부 선택은 −, 전부 ✓, 없음 ☐이며 일부 선택 가지 클릭은 전부 선택한다. 순수 leaf·부모 계산은 한 곳에 둔다. 필터의 모두 선택=빈 목록과 폼의 명시적 선택은 입력 의미가 달라 합치지 않는다(선택 칸 1-4, 배포 합의 11).
- 칸은 하나이고 펼침·드롭다운·계층 메뉴·검색 모양을 끼운다. 값·URL·검증·오류 포커스는 칸이 소유하며 닫힌 다중 선택은 고른 값을 요약한다(선택 칸 1-5).
- 선택지는 검색 선언 `check` 한 곳에서 받고 상위 변경 시 하위 값을 비운다. 같은 선언을 URL 확인과 표시가 읽어 요청 중복·늦은 이전 상위 결과를 막는다. 검색 칸은 받은 목록 거르기와 지연된 서버 자동완성을 지원하며 요청 취소·늦은 응답 처리를 화면마다 반복하지 않는다(서버 선택지 합의 3-1·3-3·3-4).
- 사용자 원문(2026-10-30): “1B 2A 3B 4A 5 옵션에 없는 값이면 없는 걸로 6 키트에 안 올림”. 입력 중 글자와 추가한 조건을 구별한다. Enter·구분 문자 연결은 프로젝트 복사본, 값 갱신은 패키지가 맡는다. 별도 입력 결합 방법은 키트에 올리지 않는다.
- 같은 모양의 값을 다르게 버리던 계산은 교정하되 전체 선택지와 서버 검색의 일부 결과를 구별한다. 준비 전 값은 보존하고 원본을 편집으로 바꾸지 않으며 표시·제출 값을 계산한다. 트리 밖 값 보존을 전제로 했던 이전 판단은 이 사용자 답이 대체한다. 보존하는 값의 상대 순서를 트리 안 값 뒤에 두는 것은 구현 선택이다.
- Form.Choice는 Form.Select와 같은 준비 상태·재시도 계약을 공유한다(조정자 2026-10-30 확인). 별도 동작 플래그를 만들지 않는다.

## 필수와 권한

- 필수 칸은 목록·작은 창·큰 폼 모두 표시한다. 목록 검색·작은 창 실행은 빈 필수에 안내와 함께 `aria-disabled`를 쓰고 키보드 접근을 유지한다. 큰 폼 저장은 필수 누락 때문에 미리 끄지 않고 제출 뒤 오류 구역·첫 오류로 안내한다(2026-10-28 필수 합의 4-1~4-3).
- `/permission`은 닫힘 기본 판정과 비동기 상태를 받는다. 불러오는 중 잠깐 열리는 것을 막기 위해서다. 권한 목록·서버 대응·메뉴 정책은 프로젝트가 맡고 판정 결과만 목록·폼에 연결한다. 목록·폼·세션 타이머가 권한 저장소를 import하지 않는다.
- `renderFailure(failure, place)`는 실패 자리를 키트가, 문구·그리지 않음(null)과 앱 경계 표현은 프로젝트가 정하게 한다.

## 미정과 결정 안 됨

- 가지 자체를 저장해야 하는 소비처가 확인되면 leaf 저장 규칙을 다시 검토한다(2026-10-28 미정).
- 서버 선택지 합의 3-2는 칸 자리의 불러오는 중·실패·재시도 모양만 합의했다. 재조회 중 선택지 유지, 실패해도 선택값·이름 보존, 수정은 원본 이름·등록은 마지막 이름 사용, 정상 빈 목록과 실패 문구 구분의 공용 채택은 작성자 제안이며 미정이다. 재시도 뒤 입력 포커스 이유와 선택지 상태 연결 결정은 유지한다.

## 검토한 대안

모양마다 칸·그룹 옵션을 늘리거나 값을 그룹별 객체로 만들면 URL·전체·복구 계산을 다시 만든다. 화면마다 별도 useQuery나 서버 검색을 두면 같은 선언과 늦은 응답 처리를 중복한다. 다른 부품 코드를 그대로 이식하면 UI·번역·아이콘 의존이 따라오므로 규칙·검사 사례를 취한다. 권한을 목록 속성으로 내장하면 권한 저장소에 의존한다. 큰 폼 저장을 미리 끄면 빈 칸을 찾기 어렵고, 모든 버튼을 늘 켜면 목록·작은 창에서 고른 사용자 결정과 어긋난다. 결과 탭 값 공유·렌더 시점 다운로드 대상도 채택하지 않는다.
