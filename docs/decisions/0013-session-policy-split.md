## 결정과 이유

활동 감지·간격 제한은 별도 선택 부품에, 세션에 묶인 시도·마감의 저장과 탭 병합은 수명 장치에 둔다. 활동 부품은 저장 형식을 알지 않는다. 임시 마감 생성, 어떤 응답을 마감으로 채택할지, 재개 실패 유예 길이, 경고 닫음과 재노출은 프로젝트에 둔다. 표시 문구용 세션 길이는 타이머의 책임에서 뺀다. 자동 첫 표본 채택·고정 유예·자동 임시 마감을 끄는 예외 옵션을 누적하지 않고 원래 정책 자리를 제거한다.

0초에 자기 진행 중 연장을 기다릴지는 같은 만료 기능 안의 필수 선택으로 받는다. 기본값은 없다. 범위는 자기 탭 요청이고 다른 탭 종료가 우선할 수 있다는 기존 한계를 유지한다. 연장 결과는 요청·채택·경고 해소 사실을 구분해 화면의 성공 판정을 대신하지 않는다.

사용자는 E(서버 마감 우선순위)를 “같은 세션의 더 늦은 서버 마감만” 공통 규칙으로 확정했다. 이것은 클라이언트 채택 규칙에 대한 승인이고 서버가 실제로 마감을 단축하지 않는다는 사실 확인이 아니다. 서버가 단축하면 화면 종료와 서버 인증 거절 시각이 어긋날 수 있다. 요청 순서보다 마감 크기를 우선하며, 탭별 저장 슬롯 병합으로 동시 쓰기의 긴 마감 유실을 막는다. 로컬 임시·유예와 서버 승인은 구별한다.

사용자는 J(경고 닫음 상태 제거)를 프로젝트 UI로 옮기도록 확정했다. 기존 DT 보이는 동작은 DT 이전 작업에서 유지한다. starter는 프로젝트 UI에서 그 연결을 관찰하는 격리 소비 검사를 제공한다. 실제 서버 계약이 없는 starter 기본 화면에 새 유휴 정책을 가정하지 않는다.

HTTP의 요청별 응답 메타 전달을 원래 전송 경로에서 보완해, 연장 요청이 전역 최신 표본 변수 없이 자기 응답의 마감을 받을 수 있게 한다.
