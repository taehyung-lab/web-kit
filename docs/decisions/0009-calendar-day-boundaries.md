# 0009. 날짜 경계 계산과 소비자 전송 정책을 분리한다

- 상태: 채택 (2026-11-09)
- 근거: 날짜 검색 소비에서 같은 현지 날짜가 시간대·서머타임에 따라 다른 절대시각 구간을 가짐. 사용자 승인으로 공통 계산만 키트에 편입한다.

## 결정과 이유

루트의 `calendarDayBounds`가 명시한 날짜·시간대의 시작과 다음 날짜 시작을 계산한다. 날짜 형식·존재 여부·시간대 오류를 결과로 구별한다. UI·서버·브라우저 기본값에 의존하지 않는 순수 계산이며, 목록/폼 어느 쪽도 import하지 않는다.

서버의 닫힌/열린 종료 경계와 정밀도는 서로 다르므로 종료 시각을 감산하지 않는다. 표시 기준 시간대·날짜 포맷·빈 값·프리셋 목록도 소비자가 선택한다. 기능의 동작 보장과 소비 연결은 web-kit-list 스킬이 소유한다.

검토한 대안: 화면별 변환 복제는 날짜 전환 오류의 수정을 분산시킨다. 서버 요청 모양까지 공용화하면 다른 서버의 종료 의미를 강요한다. 임의 datetime-local 해석까지 한 번에 공개하면 실제 날짜 검색 요구보다 입력·모호성 계약이 넓어지므로 이번에는 하루 경계만 공개한다.

## 배포 범위

기존 입구·동작을 유지하는 선택적 순수 함수 추가다. minor 후보 버전으로 포장하며 UI registry 교체는 필요 없다. 소비자는 자체 날짜 경계 계산을 제거하고 서버 연결만 유지한다.

## 재검토 조건

시간 단위 폼 소비가 생기면 임의 현지 시각의 중복/누락 처리 선택을 별도로 검토한다. 특정 시간대 규칙 변경은 실행 환경의 Intl 시간대 데이터에 따르며 검증 환경을 함께 기록한다.
