# 0009. 프로젝트 공용 경계와 소비 코드 가독성

- 상태: 2026-10-28 사용자 승인. 정식 배포까지 진행하며 실서버 확인은 제외한다.
- 범위: 특정 소비 프로젝트를 기준으로 삼지 않는다. 서버 응답 의미·문구·업무 값은 소비 프로젝트가 소유한다.
- 기존 0003~0008의 구현과 검사는 보존한다. 별도 작업의 목록·선택 칸 합의는 누락 여부를 별도로 대조한다.

| 정한 것 | 종류 | 상태 | 근거 — 가져올 것 / 다시 만들 것 | 완료 반례 |
|---|---|---|---|---|
| 실패 형태·전송·세션 회복은 키트, 응답 구조·성공 판정·코드 의미·번역은 프로젝트 | 새 동작 | 합의 | 기존 RequestFailure·HTTP 회복 검사 보존, ResponseContract 입력 추가 | 같은 코드의 의미가 다른 프로젝트를 붙이려 키트를 수정한다 |
| 목록은 이름이 드러나는 일반 JSX 부품으로 조립하고 공통 상태는 한 곳에서 관리 | 모양 | 합의 | 기존 List 상태와 부품을 이름 있는 export로 제공; starter의 필터·열·업무 처리 분리 | 배치를 옮기면 검색·선택·기간·페이지 상태가 달라진다 |
| 업무 처리 콜백에는 이름을 붙이고 짧은 값 선택·전달은 인라인 허용 | 모양 | 합의 | starter의 저장·일괄 작업 절차를 함수로 표현 | JSX 안에 요청 변환과 후속 상태 변경 절차가 섞인다 |
| 최신 구현의 진행 표시·파일 응답 처리·확인창·선택 보호를 유지 | 기존 보장 | 유지 | 0003~0008 및 기존 검사 | 통합 후 기존 검사에서 회귀가 발생한다 |
| 포장한 동일 산출물로 starter와 실제 소비처를 검사하고 CI 산출물 그대로 정식 배포 | 검사 | 합의 | docs/maintaining.md | 검사하지 않은 재포장 파일을 배포하거나 실제 서버 미확인을 통과로 보고한다 |

검사: 키트 전체 check, starter 포장 내용 검사·타입·단위·빌드·브라우저, 실제 소비처 로그인·세션·API 검사, 별도 검토자의 공용 경계 판정. 실서버 동작은 사용자 요청에 따라 미확인으로 별도 기록한다.

## 3.0.0 이후 버전

사용자 확인: 최신 3.0.0에 이번 세션 변경을 더해 다음 버전으로 낸다. 기존 버전 내용을 다시 발행하지 않는다. 응답 계약·공용 Choice·필수 조건처럼 선택적인 공개 기능이 추가되므로 `docs/maintaining.md`의 minor 기준에 따라 3.1.0이다.

| 정한 것 | 종류 | 상태 | 근거 — 가져올 것 / 다시 만들 것 | 완료 반례 |
|---|---|---|---|---|
| 목록·폼이 같은 선택 칸과 트리 값을 사용하며 모양을 교체 | 새 동작 | 합의 | 0010 1절, Base UI 공개 부품으로 구현 | 모양 변경으로 값이 바뀜, 단일에서 가지 ID 저장 |
| 가지의 전체·일부·없음 표시와 leaf 값 저장 | 새 동작 | 합의 | 0010 1-1·1-2, 기존 트리 도우미는 호환 유지 | 일부 선택인데 부모가 전체 선택으로 표시 |
| 선택지 선언 공유, 상위 변경 시 하위 정리, 서버 자동완성의 입력 지연·늦은 응답 보호 | 새 동작 | 합의 | 0010 3절 | 이전 상위·검색 결과가 현재 칸을 덮음 |
| 필수 조건은 표시·검색 차단·직접 호출·URL 진입에 동일 적용 | 새 동작 | 합의 | 0010 4절 | 빈 필수로 요청, 안내 없는 비활성 버튼 |

2026-10-29 사용자 확정: 폼 내부 참조와 두 번째 저장 방식도 개선한 뒤 3.1.0으로 정식 배포한다. 3.1.0은 아직 발행하지 않았다. 업로드 단계와 기타 작성자 제안은 이번 확정과 구분한다.


## 검증 기록 (2026-10-28)

- 최신 3.0.0 소스에서 3.1.0을 만들었다. 기존 공개 입구는 유지한다.
- 키트 타입·417개 동작 검사와 배포 기록 스크립트 3개, starter 타입·lint·31개 검사·빌드가 통과했다. 브라우저 15개는 응답 계약·선택 해제·검색 요청 보호 수정본에서 통과했고, 마지막 상세 필터 교정은 독립 검토의 관련 55개 검사로 재확인했다.
- 독립 검토에서 실제 HTTP 상태 보존, 합계 번역키, 선택 해제, 반복 검색 오류 펼침, 서버 검색 취소 수명을 교정했다. 상세 필터는 다른 칸을 입력하면 접힘을 유지하고 재검색 거절에만 펼친다. 추가 수정 요구는 없다.
- Playwright 실행 산출물인 `test-results`·`playwright-report`만 lint에서 제외했다. 별도 검토자가 실제 소스와 E2E 검사 파일은 계속 검사됨을 ESLint API로 확인했다.
- starter와 실제 소비 프로젝트에 같은 tarball을 설치했다. 파일 SHA-256은 `c90f1e284e5e80b06232340b97036afae15627185e24daa835a57896268e71a5`다. 실제 소비처의 세부 화면·검사 결과는 해당 프로젝트 결정 기록에 둔다. 정식 배포 파일은 main CI 산출물과 최종 대조한다.
- 실서버 검사는 사용자 요청에 따라 수행하지 않았다.

## 추가 폼 기능 검증 (2026-10-29)

- Node 24.19.0에서 키트 타입·432개 검사와 산출물 기록 검사 3개, starter 타입·lint·33개 검사·빌드, 브라우저 16개가 통과했다. 마지막 오류 원문 fallback 보완은 키트 관련 15개와 starter 번역 소비 검사로 재확인했다.
- 독립 검토에서 두 저장 응답 타입 분리, 전체 입력 오류 문구 보존·번역, 참조 정리 후 최종 값 검증, 두 번째 검증의 실패·초점·교정 후 재시도 검사를 보완했다. 최종 독립 회귀 검사 15개가 통과했고 남은 수정 요구는 없다.
- 참조 검사는 이전 반영 순서로 되돌렸을 때 text·checkbox 두 경우가 실패하고 수정 순서에서는 통과했다. 저장 성공 후 폼 초기화와 제출 실패 후 재검증을 구분한다.
- 최종 검사 파일 SHA-256은 `39f2428813caeec16bffc6d39cb2f14ff2313ff7e180c46520966fbb74a43863`이다. CI에서 같은 파일을 검증하며 main 통과 산출물을 그대로 발행한다.
