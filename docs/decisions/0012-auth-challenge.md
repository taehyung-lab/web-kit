# 0012. 4.1 로그인 인증 단계의 공통 동작

- 출처: 2026-10-29 상위 DT 재구축 계획 합의 3·단계 1, 사용자 원칙 “로그인 로직은 REF 기준, UX는 1.5 기준”, A1 비교 질문 Q1–Q10에 대한 조정자의 사용자 원칙 적용 답변.
- 4.0.0-rc.3에서 기존 공개 계약을 유지하는 추가이므로 4.1.0-rc.1이다. 원격 발행 결정은 포함하지 않는다.
- 보장의 정본은 `packages/web-kit/skills/web-kit-auth/SKILL.md`다.

| 결정 | 이유 | 근거 |
|---|---|---|
| `/auth`는 로그인 전 인증의 계산·진행을 맡고 화면은 registry 복사본으로 둔다 | 인증 성공 뒤 세션과 인증 전 단계를 서로 섞지 않으면서 중복 구현을 없앤다 | 상위 합의 3, 0003 §4, 0011 |
| 절대 만료 시각, 같은 로그인 안 기한 유지, 새 로그인 기한 재설정 | 탭 지연·방식 전환이 코드 수명을 늘리지 않아야 한다 | Q1·Q2; REF useRemainingSeconds, DT origin/v2 product/decisions.md 인증 절 |
| 만료 뒤 입력은 허용하고 확인·Enter 제출을 차단한다 | REF 동작을 따른다 | Q3 답변. 최초 지시의 입력 잠금은 조정자가 근거 없는 조건으로 철회; 독립 판정 대상 |
| 중복 실행을 즉시 막고 취소·전환 뒤 늦은 응답을 버린다 | 취소한 로그인 결과가 다시 세션을 만들지 않게 한다 | Q5·Q6, REF useTwoFactorSubmit |
| 숫자 검증은 공통, 자리수와 기한·재전송 대기는 프로젝트 입력 | DT/REF 분기 없이 정책 값만 받는다 | Q4·Q7, 재전송 대기 답변 |
| 인증 상태는 메모리에 두며 등록 흐름·QR 계약·실패 코드·문구·잠금 판정은 프로젝트 소유 | 서버와 제품 차이를 공통 패키지의 기본값으로 만들지 않는다 | Q8–Q10 |
| 서버 시계는 기존 유휴 타이머의 보정을 분리하여 같은 객체를 공유한다 | 로그인 전후의 시간 계산이 어긋나지 않게 한다 | 상위 합의 3, session-idle.ts |
